# RideNav audit — 6 November 2026

Scope: all seven watch pages, settings, transport, navigation engine, providers, storage, Android notification bridge and relay. Source and mocked-platform verification are distinct from physical-device acceptance. No claim of flawless operation or five-year vendor compatibility is made.

## Implemented corrections in 1.4.0

- Cancelled routes, stale heartbeats and instructions mentioning a destination do not falsely report arrival. Stale bridge responses clear cached live guidance; subsequent routes recover automatically.
- Watch home refreshes readiness continuously. Both cloud failure and stale cloud state try the authenticated local bridge. Authentication errors and service outages have separate messages.
- Native phone fetches are bounded to four outstanding operations, including operations abandoned by UI watchdogs. Zepp does not document fetch cancellation; if all native operations remain hung, restarting Zepp may still be necessary. No unsupported cancellation behavior is assumed.
- Route requests allow sequential geocoding/directions deadlines. Synchronous BLE errors become rejected promises; responses must match request identity and expected type. Duplicate routing requests share their original result.
- Setup, home and diagnostics ignore responses after destruction; setup and diagnostics suppress duplicate actions. Google navigation settings failure cannot restore display overrides after page closure.
- Offline demo loads its bundled route directly on the watch. Blank coordinates geocode the entered destination instead of silently selecting 0°, 0°.
- Mapbox maneuvers map to actual route vertices in order, using distance to disambiguate repeated locations. Simplification preserves maneuver vertices. Invalid steps/indices fail visibly. Old GPS samples are rejected and long GPS gaps reset position smoothing.
- Manual Reroute actually requests a new route on the next fix, including on-route fixes. Reroute responses cannot update a closed/recreated page. Arrival cannot resurrect a cleared active session from the remainder of the GPS callback.
- Button text now has stronger contrast: dark text on green/amber actions and a darker blue default button.
- Watch menu/footer geometry stays further inside the round display. Instruction height and text bounds improve readability. Delayed guidance does not trigger fresh turn haptics; distance changes no longer vibrate on every single meter update. Resume clears End confirmation.
- Built-in navigation honors text size, sunlight contrast, haptic strength, early alerts and important-only alerts. Google navigation accepts live settings changes. Unsupported day/night choices were removed from the phone settings.
- Android listener requests rebinding after disconnect, tolerates unavailable notification lists and null extras, and reports actual connection independently of granted access. Route completion clears the mirrored fallback notification. Local socket ownership is safe across stop/start and each response reads a synchronized state snapshot. Idle scans refresh the local heartbeat.
- Android JSON output escapes notification control characters correctly. Relay publisher identities allow sequence restart after process recreation/clock rollback and suppress late updates from retired publishers. An unconfigured relay secret cannot authorize a request.
- Routing credentials stay on the phone; watch settings messages and saved sessions exclude tokens. Rerouting uses current phone credentials after rotation.
- Custom HTTPS backend support now has an authenticated, validated routing contract; see BACKEND.md. This is an integration capability, not a deployed routing server.
- Zeus and ZML are pinned to tested versions. Watch/phone versions align at 1.4.0.

## Deployment and physical acceptance gates

1. Review the Git changes before push. No Git push, relay deployment or device installation is performed by this audit.
2. Deploy the relay update to enable publisher-identity recovery. The new Android bridge keeps a time-based starting sequence for compatibility with the current relay before that deployment. Once a session uses publisher identities, old bridge versions without identities cannot replace that session; retain coordinated rollback builds/configuration.
3. The development Zepp app ID/vendor placeholders are sufficient only for the existing development workflow. A public store release requires the owner's real Console identity, developer contact and privacy disclosures. These cannot be invented.
4. Notification parsing currently supports English Google Maps wording and common metric/imperial units. Other phone languages require actual notification fixtures and localization work.
5. Confirm actual 480×480 round-screen rendering, text overflow, wrist/palm behavior, four-hour battery use, and repeated phone/watch reconnection on hardware. Mocked widget tests do not certify rendering or firmware behavior.
6. Keep Zepp paired and allowed to run, Notification Access enabled, and Android background/battery restrictions configured. Bluetooth and internet alone do not override revoked permissions, a force-stopped phone app, watch foreground restrictions, or an unavailable third-party service.

## Device test matrix

On the actual phone and original Balance, repeat Bluetooth off/on, data off/on, Wi-Fi/mobile transition, 30-minute phone lock, Zepp recreation, listener disconnect/rebind, watch page exit/reopen, phone/watch restart, route cancel/start, relay authentication/service failures, and permission removal/restoration. Record recovery latency, duplicate alerts, stale-arrow duration and any manual intervention. Verify that cancellation never reports arrival and stale data is visibly marked or cleared.

Run a four-hour route containing long straight legs, frequent turns, rerouting, GPS loss and large/sunlight text. Capture every page with the longest supported text. Measure battery drain and thermal behavior; confirm display overrides clear after every exit.

## Five-year operating plan

Target service through November 2031 with quarterly health/recovery checks and regression trials after Google Maps, Zepp, Android and watch firmware updates. Preserve signing keys, private relay settings, account recovery and known-good watch/APK builds in encrypted backups; test restoration annually. Maintain Cloudflare availability and credential rotation. Vendor notification formats, OS background rules and firmware changes may require future app updates.
