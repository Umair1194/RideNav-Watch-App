# Connecting/crash repair — 9 November 2026

The watch pages and shared transport used global setTimeout/clearTimeout. Zepp OS exposes these functions through @zos/timer; the shared transport now receives the watch timer functions through its page context. This removes reliance on browser/Node globals for polling and request watchdogs. Page cleanup also handles a timer ID of zero.

Validation: 53 app tests, 5 relay tests, and project validation pass. A regression test exercises injected platform timers and a zero-valued timer handle. A watch-specific 1.4.1 developer preview compiled and installed successfully on the connected original Balance.

Physical evidence: the watch produced 13 successful BLE response events over approximately 34 seconds after startup; the captured watch-app logs contained no runtime errors. The user confirmed the navigation screen now shows Ready / waiting for Google Maps rather than remaining at Connecting. A subsequent remote screenshot attempt timed out when the phone returned to its charging screen, so no new navigation screenshot was verified. The user then started Google Maps navigation and confirmed that turn directions and distance appeared on the watch. The live relay reported an active route and a fresh heartbeat. Disconnect/reconnect endurance and long-duration battery behavior still require separate verification; no blanket guarantee of perfect operation is made.

The phone companion and relay health check were online. No relay changes were deployed as part of this repair. Source changes are local pending review/push.
